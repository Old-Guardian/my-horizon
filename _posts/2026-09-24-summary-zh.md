在英国政府发出的强制访问令压力下，苹果已对英国 iCloud 用户撤下“高级数据保护”（ADP），使受影响的数据类别回退到由苹果持有密钥、可依法响应执法请求的“标准数据保护”级别。一篇分析这一退让的文章在 Hacker News 上获得 314 分、321 条评论，围绕技术后果与治理先例展开讨论。 这实际上把 iCloud 用户切成了两级加密体系：英国用户在备份、照片、备忘录和云盘等数据上失去端到端加密，而其他地区用户仍然享有。由于此事表明政府可以迫使平台削弱安全架构而非在法庭上对抗，它为其他司法辖区树立了先例，这正是隐私倡导者所担心的。 ADP 是一项可选设置，可把端到端加密的 iCloud 数据类别从 14 个提升到 23 个；包括 iCloud 钥匙串和健康在内的 14 个基础类别无论如何都保持端到端加密，而其余类别——iCloud 备份、照片、备忘录、iCloud 云盘等——对英国用户回退为“标准数据保护”。有评论者强调，回退层级的影响是实质性的：在常见使用方式下，英国用户的端到端加密密钥材料可能因法律请求而暴露，因此这种分级并非只是表面差别。

## [文件通知接口被滥用：可实施按键时序与点击劫持攻击](https://lwn.net/Articles/1096431/) ⭐️ 8.0/10

来自格拉茨理工大学、由 Sudheendra Raghav Neela 领衔的研究团队发布了一篇论文和公开演示，说明 Linux inotify 等文件通知接口可被滥用来监视用户活动，影响范围覆盖 Android、Linux、macOS 和 Windows。在 Linux 上，他们仅用 inotifywatch 监控某个目录（即使没有该目录内文件的读取权限）就实现了按键间时序攻击，并通过监视 /usr/bin/pkexec 探测 Polkit 何时弹出认证提示，从而在 KDE 5 和 KDE 6 上实现了 UI 重定向（点击劫持）攻击。 该研究打破了“文件通知接口不涉及隐私”的常见假设：一个没有文件读取权限的非特权进程，仍能推断用户的输入节奏，甚至通过伪造密码窗口窃取凭据。这对操作系统的沙箱模型、Linux 及其他平台的桌面安全，以及任何把文件系统元数据视为低风险信息的威胁模型都构成冲击。 Linux 内核只是在 1 月发布的 5.10.248、5.15.198、6.1.160、6.6.120、6.12.65 和 6.18.3 内核中加入了部分缓解措施（CVE-2025-68788），而这两类攻击至今依然存在。项目网站提供了攻击演示，以及一项可防止密码提示窗口失去焦点的缓解方案。

rss · LWN.net · 9月24日 17:40

**背景**: inotify 是 Linux 的文件系统通知接口：程序对文件或目录注册监视后，在它们被访问、修改或创建时会收到事件，文件监视工具和桌面索引器就靠它跟踪变化。由于这些事件会对路径上的操作触发，即便文件内容不可读，它们也可能成为泄漏时序信息的侧信道。按键间时序攻击利用的是输入节奏本身就携带足够信息、可用于重建或推断输入内容；而 UI 重定向（点击劫持）攻击则是诱导用户与叠加在合法界面之上的伪造界面交互，是典型的“混淆代理”（confused deputy）问题。

## [WordPress get_page_template() 曝出严重 RCE 漏洞并已修复](https://lwn.net/Articles/1096195/) ⭐️ 8.0/10

WordPress 披露了其页面模板解析函数 get_page_template() 中存在一个严重的、在特定条件下可被未认证攻击者利用的远程代码执行（RCE）漏洞，并已为最新分支发布修复（据报道版本为 WordPress 7.1.2，编号 CVE-2026-87902），同时将该修复向后移植至 4.7 分支。该漏洞同样影响 ClassicPress 分支，但该项目尚未发布安全更新。 WordPress 驱动着互联网上极大比例的网站，因此核心代码中可被未认证利用的 RCE 属于高影响安全事件：任何运行未修复版本的站点都可能暴露在风险之中。修复被向后移植到 4.7 分支，说明受影响代码的覆盖面之广，即便长期未更新的老旧安装也不能再被视为“已经过时所以安全”，必须进行修补。 根据安全公告，该漏洞仅在有限条件下才能被利用，因此并非无条件即可触发的远程攻击；具体前置条件在漏洞报告中已有说明。由于 get_page_template() 位于页面模板解析流程中而非插件里，修复必须由核心代码提供，而 ClassicPress 用户目前尚无官方补丁可用。

## [LLM 残差流被用作隐蔽信道，可在气隙环境中泄露机密](https://arxiv.org/abs/2609.27996) ⭐️ 8.0/10

一篇新论文（arXiv:2609.27996，作者为 Mingyuan Li 等七人）提出了名为 ResidualMux 的残差流隐蔽信道攻击：被攻陷的运行时 hook 会把消息映射为码字并注入模型中间层的残差流，离线观察者只需一个简单的线性解码器即可还原信息。该工作在覆盖 7 个架构家族、共 11 个模型上进行了评估，其中 9 个模型的信息恢复率达到 91%–100%，且无需重新训练模型、不修改权重、也不需要攻击者控制的出网通道。 它打破了"只要只导出诊断用的激活值工件，气隙或受限环境就安全"这一常见假设——因为一份格式合法（schema-valid）的激活文件可能悄悄夹带了原本无权跨界的敏感数据。由于篡改发生在推理运行时而非模型权重中，推理基础设施的供应链与内部人员威胁会直接演变为数据外泄风险，对 AI 安全与隐私团队具有现实意义。 为了让隐藏信号既保持可恢复性又不引人注意，注入强度按照局部残差范数进行缩放（使用 signal-to-residual-norm ratio），由此产生的扰动对模型输出分布的影响极小，KL 散度仅为 0.001–0.007。激活值层面的检测器表现接近随机猜测（AUC ≤ 0.56），作者还指出所测试的事后防御手段都无法可靠地消除该信道。

rss · arXiv cs.CR · 9月24日 04:00

**背景**: 在 Transformer 大模型中，"残差流"是贯穿各层的隐藏状态累加向量，每个模块都会从中读取并写回信息；由于它是加性的高维通道，其中微小的扰动就能编码信息并保留到后续层。所谓"运行时 hook"是一种插件机制（思路类似于 vLLM Hook 等工具），允许使用者在推理过程中查看或修改模型内部状态，因此被攻陷的 hook 无需改动模型文件即可作恶。气隙环境是指被刻意切断外部网络连接的部署环境，它们通常允许导出部分激活值或诊断工件用于调试与监控，而隐蔽信道正是利用了这类被许可、看似无害的流量。已有研究表明，拒绝等概念在网络的较早层就能从残差流激活中被线性解码，这也是本攻击只需一个简单线性解码器的原因。

## [谷歌开源 AX：面向 AI 智能体的声明式编排运行时](https://github.com/google/ax) ⭐️ 7.0/10

谷歌开源了 AX（Agent eXecutor），这是一个高吞吐量的声明式编排运行时，构建在 Agent Substrate 之上，用于在集群中沙箱化地执行自主智能体工作负载。它提供四个核心原语——Task、Workspace、Gateway 和 Model——通过 ax.io/v1alpha1 格式的 YAML 清单声明，并用单条 `ax apply -f task.yaml` 命令下发，同时还提供 `ax watch`、`ax ssh`、`ax suspend` 和 `ax resume` 等命令行操作。 AI 智能体正在成为一种独立的工作负载类型，介于无状态微服务与一次性批处理任务之间，但目前能够以大规模、可隔离、可控成本方式运行它们的成熟工具仍然很少。凭借谷歌的背书以及项目登上 GitHub Trending，AX 有可能像 Kubernetes 标准化容器编排那样，影响开发者对智能体编排的标准化方式。 项目明确标注为尚未稳定：谷歌警告说核心概念、协议和规范仍在打磨中，稳定版发布前很可能会出现重大的破坏性变更。每个原语都对应一个具体需求——Task 负责在带 CPU/内存限制的沙箱中执行，Workspace 用于预先接入 Git 仓库、MCP 服务器和技能包，Gateway 用于把出站流量限制在显式的主机白名单内，Model 则用于配置平台自身使用哪个 LLM 并从 Kubernetes Secret 中读取凭据。

**背景**: 智能体编排指的是在统一系统中协调多个专用 AI 智能体，使它们共同完成一个共享目标；而编排运行时则是执行期的控制层，负责决定由哪个智能体执行、重试失败步骤或分支到新的路径。AX 有意沿用 Kubernetes 的约定——YAML 清单、kind 类型、apply/watch 等动词——让熟悉 Kubernetes 的开发者能快速上手；文档中提到智能体可能“在循环中烧钱”，反映的正是智能体运行会持续消耗付费的模型 API 调用和工具服务这一现实。
