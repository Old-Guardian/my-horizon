## [谷歌研究院发布 TimesFM 3.0 时间序列基础模型](https://github.com/google-research/timesfm) ⭐️ 8.0/10

谷歌研究院发布了 TimesFM 3.0，这是一个预训练的时间序列基础模型，现已在 Hugging Face 上提供。它引入了原生多变量预测、灵活的协变量支持，并在 fev-bench、TIME 和 GIFT-Eval 基准测试中均排名第一。 TimesFM 3.0 在多个基准测试中的领先性能以及其零样本泛化能力，可能改变预测的实际执行方式，使其能够在各个领域以最少的调参实现准确预测。它与 Google 的 BigQuery ML 和 Vertex AI 的集成使其对企业用户具有可及性。 TimesFM 3.0 引入了原生多变量和协变量支持，包括仅过去和过去+未来的动态协变量。然而，其预训练权重采用非商业许可（timesfm-non-commercial-license-v1.0）发布，仅限于非商业、非生产用途，而早期版本（直至 2.5）仍为 Apache-2.0。

rss · GitHub Trending - Daily · 9月4日 18:53

**背景**: TimesFM 是一个用于时间序列预测的 decoder-only 基础模型，在 1000 亿个真实世界时间点上进行了预训练。它采用分块解码器注意力架构，受大型语言模型启发，能够以零样本方式进行预测，无需针对特定任务重新训练。自 2024 年 ICML 引入以来，它已被整合到 Google 的产品中，如 BigQuery ML 和 Vertex AI，使其可用于企业级应用。

一篇新论文发现，大语言模型的未嵌入几何中存在一个'无知方向'，它编码了训练语料的 unigram 分布，充当贝叶斯先验。研究显示，将最终预测状态投影到该方向会得到每个 token 的先验加载因子λ，随着上下文信息量增加，λ会下降。 这为理解大语言模型如何处理不确定性提供了新的几何解释，将贝叶斯先验与内部表示联系起来。它有望提高模型的可解释性和校准性，并可通过操控λ来引导模型行为。 该'无知方向'在测试的所有四种模型家族（Llama、Qwen、Gemma、Pythia）中都存在，参数规模从 0.4B 到 405B 不等。投影将预测状态分解为两个正交向量，分别对应指数为λ的 unigram 先验和上下文驱动的似然，且λ在引导预测中具有因果活性。

rss · arXiv cs.LG · 9月4日 04:00

**背景**: 语言模型通过为词汇表中的每个可能 token 分配概率来预测下一个 token。Unigram 分布反映了训练语料中 token 的整体频率，当模型对下一个 token 不确定时，它可以作为先验。贝叶斯更新将这一先验与上下文证据结合以产生后验。本文表明，这种更新在未嵌入矩阵中以几何方式实现，其中特定方向编码先验，而加载因子λ调节其影响。

## [方程重铸：跨参数 PDE 的零样本算子学习](https://arxiv.org/abs/2609.02982) ⭐️ 8.0/10

该论文提出‘方程重铸’框架，将参数化算子学习重构为学习单一规范算子，从而实现新参数域上的零样本预测。该框架统一了稀疏异构数据集，并处理多参数、非线性和奇异 PDE 设置，成功应用于托卡马克模拟。 这项工作解决了科学机器学习中的关键挑战：训练分布外的外推、稀疏异构数据的整合，以及奇异设置的处理。其在保真托卡马克模拟中的应用凸显了对聚变研究的实际意义。 方程重铸从控制方程解析地推导参数引起的算子变化，并将其吸收到有效源项中，同时将收敛损失作为重铸迭代失败的内部警示信号。在托卡马克模拟中，通过规范域映射，将四种设备几何形状的电子温度数据统一到一个联合训练的算子中。

rss · arXiv cs.LG · 9月4日 04:00

**背景**: 算子学习是一种机器学习范式，学习函数空间之间的映射，例如从初始条件或参数到偏微分方程解的映射。参数化偏微分方程涉及改变解算子的物理参数，要求模型能跨参数泛化。传统数据驱动模型通常需要广泛覆盖参数空间，并可能在训练分布外悄然失败。方程重铸通过解析地将参数变化纳入算子，避免了这些问题，使单一规范算子能处理多个参数域，从而提高数据效率并实现零样本外推。

本文提出了干预度量 RFIS 和 RPD，用于分析基于 RoPE 的 Transformer，揭示了由全局位置带（GPBand）分隔的检索头和位置头的分类。还提出了一种新的混合架构 HwH，提高了零样本长上下文外推能力。 这项工作为混合架构中注意力类型的分配提供了基于证据的基础，超越了经验法则。研究结果为设计未来更有效处理长上下文的基础模型提供了原则。 该分类在 Qwen3 系列模型和 Llama3.1 上通过受控 Transformer 得到验证，表明边界遵循训练长度位置尺度。HwH 使用 NoPE 全注意力进行全局检索，使用线性注意力进行局部位置建模，FA 与 LA 比例低于 1:3，在保持强大语言建模能力的同时改善长上下文外推。

## [ObserverBench：评估干预与控制的机械估计基准](https://arxiv.org/abs/2609.03026) ⭐️ 8.0/10

论文提出了 ObserverBench，这是一个基准框架，将估计准确性与行动损失分离，以测试机械可解释性估计器是否适用于干预和控制任务。它提供了在 GPT-2-small 和 Qwen2.5-7B 上的实验，表明成对观察者能准确预测未见效果但不总能选择更好的行动，而基于行动损失训练的观察者会选择更低损失的行动。 该基准通过将估计准确性与行动质量分离，解决了机械可解释性中的一个关键缺口，这对 AI 安全研究至关重要，因为基于有缺陷估计的干预可能导致有害行动。它提供了正式框架和可运行的基线，以指导未来在表示工程和安全监控方面的工作。 该基准为每个任务固定了模型、信息边界、允许行动、决策规则、留出案例和损失，并分别报告估计准确性和行动导致的损失。在 Qwen2.5-7B、Gemma-2-9B-it 以及未来冻结的 Qwen3.5-9B APPS 任务上的实验表明，AUROC 对监控器的排名可能与部署损失不同，且稀疏 SAE 读数在披露的激活密度或检查点不匹配下落后于其层匹配的密集控制。

rss · arXiv cs.LG · 9月4日 04:00

**背景**: 机械可解释性旨在逆向工程神经网络的内部机制（如特征和电路），以理解它们如何计算输出。被称为观察者的可解释性估计器提供内部估计，可指导激活引导、电路移除和安全监控等干预。然而，平均准确的估计仍可能导致糟糕的行动，因此 ObserverBench 通过评估观察者所启用的行动质量，而不仅仅是估计准确性来评估观察者。

## [LeanStream：面向端侧 LLM 推理的推测与细化流式框架](https://arxiv.org/abs/2609.03079) ⭐️ 8.0/10

该论文提出了 LeanStream，一个流式推测与细化框架，通过将 GPU 执行与存储 I/O 重叠，实现高效的端侧 LLM 推理。与先前的端侧 LLM 推理系统相比，LeanStream 在先前系统达到最佳吞吐量时，将内存使用减少了 4.8 倍至 7.5 倍，同时将令牌生成吞吐量提高了 1.6 倍至 2.1 倍。 这解决了端侧 LLM 推理中精确稀疏决策与早期 I/O 重叠之间的根本性权衡，使得在移动和嵌入式设备上的实际部署成为可能。它显著提高了效率，使大型模型在资源受限的硬件上变得可行。 LeanStream 通过利用部分 GPU 结果逐步细化计算、加载和缓存保留优先级，实现细粒度重叠。它在移动和嵌入式平台上均有实现，实现了 4.8 倍至 7.5 倍的内存减少和 1.6 倍至 2.1 倍的吞吐量提升。

rss · arXiv cs.LG · 9月4日 04:00

**背景**: 端侧 LLM 推理面临模型权重超过可用 DRAM 的挑战，因此系统通常将权重卸载到 SSD 或闪存存储。为减少 I/O，一些系统利用激活稀疏性，但存在权衡：精确的稀疏决策需要最新的上下文，而高效的计算-I/O 重叠需要早期预测。先前的系统要么串行执行，要么产生冗余的权重获取、额外计算和缓存开销。LeanStream 通过推测与细化框架解决了这一权衡。
