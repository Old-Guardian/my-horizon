## [谷歌预览 Gemini 4 Argon：主打智能体能力的前沿模型](https://blog.google/innovation-and-ai/models-and-research/gemini-models/gemini-4-argon/) ⭐️ 8.0/10

谷歌发布了新一代前沿模型 Gemini 4 Argon 的预览版，主打智能体（agentic）能力，官方称其在编程、推理、多模态以及长时间多步骤任务上表现突出。谷歌表示会继续收集早期测试者的反馈、迭代安全护栏，然后尽快向开发者、企业和普通消费者开放 Argon。 这是前沿模型持续高频发布中的又一个节点，也把“智能体自主性”——即模型不只是回答问题，而是能规划和执行多步骤任务——进一步推向企业级工作流。无论是超大规模云厂商还是创业公司，任何基于前沿大模型做开发或与之竞争的一方，都会受到这些能力从预览走向正式开放速度的影响。 这只是一次早期预览而非正式发布，具体技术规格仍然很少；第三方评测网站 Artificial Analysis 将“Gemini 4 Argon (High)”配置列为智能水平领先的模型之一，且相对同类模型价格合理。有报道指出该模型最初只面向部分合作伙伴（包括网络安全领域的伙伴）开放，这与谷歌强调仍在打磨安全护栏的说法一致。

## [Anthropic 发布 Claude Sonnet 5.5：提速 30%、成本最高降低 30%](https://simonwillison.net/2026/Sep/28/claude-sonnet-5-5/) ⭐️ 8.0/10

Anthropic 发布了 Claude Sonnet 5.5，官方称其运行速度快 30% 以上、大多数任务的成本最多降低 30%，定价与 Sonnet 5 持平，却在所有基准测试上都超过了前代。Simon Willison 的实测记录显示，在 "xhigh" 思考强度下它以 5.74 美分、41 秒生成了质量不错的自行车鹈鹕 SVG，但在 "max" 强度下存在可复现的失败：耗尽 128,000 tokens（约 1.28 美元）却未能产出任何结果。 对任何基于大模型构建产品的人来说，一个更快、更便宜且性能仍属前沿的 Sonnet 是一次实质性的平台升级——同样的工作负载无需降级模型，成本更低、速度更快。同样重要的是，Sonnet 5.5 现在成为 claude.ai 免费层的默认模型，使 Anthropic 的免费服务在能力上明显强于 OpenAI 基于 Luna 5.6 的 ChatGPT 免费层。 最值得注意的局限是推理预算导致的失败模式：在 "max" 思考强度下，模型耗费了 128,000 个思考 token、花费 1.28 美元，却始终没有输出 SVG，与之前 Opus 5.5 出现的同一缺陷如出一辙；而在 "xhigh" 强度下只需 5.74 美分即可得到可用结果。Willison 还指出，Sonnet 5.5 在某些编码任务上已接近 Opus 5.5，同时 Anthropic 表示 Haiku 5.5 仍将在“未来几周内”推出。

rss · Simon Willison · 9月28日 22:07

**背景**: 目前许多大模型都提供“思考强度”旋钮——如 low、medium、high、xhigh 和 max 等等级——用于控制模型在给出答案前可以生成多少内部推理 token。这些思考 token 与输出 token 一样计费，因此即便最终答案很短，高强度设置也可能让成本和延迟成倍增加。Willison 那个非正式的“骑自行车的鹈鹕”提示词要求模型生成一幅 SVG 绘图，如今已成为对比新模型发布时被广泛采用的快速冒烟测试。

## [B 站开源 Index-Translate 多语言翻译模型家族，覆盖 150 种语言](https://www.ithome.com/1/008/914.htm) ⭐️ 8.0/10

9 月 30 日，哔哩哔哩 Index LLM 团队正式发布 Index-Translate 多语言翻译模型家族，该系列基于 Qwen3.5 构建，文本模型提供 2B、9B 与 35B-A3B（preview）三个规格，权重已在 Hugging Face 与 ModelScope 开放。除核心文本翻译模型外，家族还包含用于生成目标语言字幕与配音的 Index-Echo、按指定音节数调整译文的 Index-Homura，以及处理整篇文档的 Index-NativeLong（简称 Index-Nailong）。 2B/9B/35B-A3B 三档尺寸全部开放权重，意味着这套覆盖 150 种语言的翻译系统可以被本地部署、微调和二次开发，用于本地化、社区内容处理和多语言产品，而不必依赖封闭 API。此外，它还把多语能力延伸到语音配音和长度受限翻译，这两类能力在大多数开源翻译模型中基本缺席。 35B-A3B 采用混合专家（MoE）架构，总参数 35B 但每个 token 仅激活约 3B 参数，因此在保留较大容量的同时把推理成本压低到接近小尺寸稠密模型。官方给出的证据仅限于精选案例，例如在《最终幻想 XIV》社区语境中，Index-Translate-9B 把“狒瘾”正确译为“the FFXIV itch”，而 Hy-MT2-7B 则直译成“monkey addiction”；目前尚无第三方基准测试结果。

rss · IT HOME · 9月30日 13:24

**背景**: Qwen3.5 是阿里巴巴推出的开放权重基础模型家族，以宽松许可证发布，常被用作各类垂直领域微调的底座，近期已有多个翻译和推理模型基于它构建。混合专家（MoE）是一种每次只激活网络中部分参数的架构，这也是 35B 模型能以接近 3B 模型的速度和成本运行的原因。如今翻译模型的差异点已不在单纯的流畅度，而更多体现在俚语与社区表达、格式约束、术语控制以及长文档一致性上——这正是 B 站此次重点展示的几个方向。

## [OpenAI 发布 GPT-6.1 Sol，价格仅为 Astra 的五分之一](https://openai.com/index/introducing-gpt-6-1-sol) ⭐️ 8.0/10

OpenAI 发布了新模型 GPT-6.1 Sol，号称在编程、电脑操作（computer use）和专业工作场景下具备接近 Astra 的智能水平，而 API 的输入与输出 token 价格仅为 Astra 标准价的五分之一。该发布将 Sol 定位为略低于旗舰模型 GPT-6 Astra 的一个更廉价的档位。 如果这一价格承诺属实，那么构建编程智能体、电脑操作自动化和专业工作类应用的开发者就能以极低成本获得接近前沿的能力，这将显著改变大规模运行智能体任务的成本结构。这也表明前沿模型厂商之间的价格竞争仍在持续，推动高能力模型以更低价格进入更广泛的开发者生态。 该发布公告缺乏技术细节：没有给出基准测试分数、上下文窗口大小、知识截止日期、速率限制，也没有除与 Astra 价格对比之外的具体上线日期。五分之一的说法是相对于 Astra 的 API 输入与输出 token 标准价格而言，但公告中并未披露绝对的每 token 价格。

rss · OpenAI News · 9月29日 10:00

**背景**: OpenAI 的 GPT-6 Astra 是该公司面向商业用途的最强模型，专为复杂工作流中的高级推理与电脑操作而设计。“电脑操作”（computer use）指的是让 AI 模型直接操作软件——点击、输入、浏览界面——而不仅仅是通过定制 API 做出回应，Anthropic 等公司也在研发这类能力。这类模型的 API 定价按输入和输出的 token 计费，因此价格降低到五分之一会直接降低长时间、频繁调用工具智能体任务的成本。

该论文提出了 Simple Agentic Robot Memory（SimpleARM），一种叠加在冻结通用机器人策略之上的免训练记忆层：它从任务指令中解析出需要监控的内容，用冻结的感知工具在线维护紧凑的类型化状态，仅在当前子目标依赖历史时才检索该状态，并在执行前用当前视角对召回实体进行落地校验。在 RoboMME 基准的全部 16 项任务、3 个策略随机种子上，SimpleARM 取得 67.17% 的平均成功率，而最强的非 oracle 基线为 44.51%。 现有的机器人视觉记忆系统大多只是保留或压缩过去的画面，但控制还需要从交互中产生的状态，例如持续的身份关联、累积的进度和有序的步骤流程，而这些信息往往不会显式出现在任何单帧图像中。由于 SimpleARM 无需重新训练即可作用于冻结的策略，现有通用机器人策略能够在不做昂贵微调的情况下获得依赖记忆的能力，这对具身智能的落地部署以及领域对“机器人记忆”的理解方式都有重要意义。 匹配的消融实验显示出机制层面的特异性：移除关系、指代、进度或路线状态后，恰恰是在需要检索该状态来控制的任务上出现大幅性能下降，而对其他任务基本没有影响。评估范围仅限于 RoboMME——一个专门考察依赖记忆的机器人操作任务的基准，其所要求的历史信息在当前观测中已不可见；且整个过程中底层策略始终保持冻结。

rss · arXiv cs.RO · 9月30日 04:00

**背景**: 通用机器人策略（包括 Octo 这类视觉-语言-动作模型）通常在大规模数据集上训练，把视觉与本体感知观测直接映射为动作，因此大体上是马尔可夫式的，对回合早期发生的事情一无所知。RoboMME 是一个面向记忆增强机器人操作的大规模基准，围绕四个记忆需求各异的任务套件构建，其任务仅凭当前画面无法完成。SimpleARM 借鉴了 LLM 智能体中的“智能体记忆”思路——即一个外部的、结构化的存储，由策略按需查询——并将其用于机器人控制，而不是简单保留原始视觉历史。

## [研究：LLM 智能体的安全判断与实际行动仅弱耦合](https://arxiv.org/abs/2609.35870) ⭐️ 8.0/10

一篇新的 arXiv 论文（2609.35870v1）研究了为什么大语言模型智能体能够正确判断某个动作应当被阻止，却仍然倾向于执行它，并在三个开放权重语言模型上进行了测试。作者发现，安全预测性信息仍可从动作状态中恢复，从而排除了简单的“信息丢失”解释；而能够稳定把显式安全判断推向 BLOCK 的干预，对动作偏好的改变远小于直接作用于动作的干预。 这一结果表明，仅提升安全识别能力或自我批判能力未必能让智能体更安全，因为支撑安全判断的计算并未可靠地接入动作选择过程。这对所有构建或部署 LLM 智能体的人都很重要，因为它把智能体对齐问题重新定义为“评估与行为之间的因果耦合”问题，而不仅仅是知识或意识问题。 论文指出，判断控制子空间与动作控制子空间仅部分重叠，并且在正交于判断控制子空间的方向上依然存在有效的动作控制。这种不对称性即使在同一条“判断到动作”的轨迹内部也依旧存在：对判断的强上游控制并不能转化为对动作偏好同等强度的下游控制。

rss · arXiv cs.CR · 9月30日 04:00

**背景**: LLM 智能体是指被赋予工具、记忆和决策执行循环的语言模型，它们不只是生成文本，还会决定并执行动作。“开放权重”模型指训练后的模型权重被公开发布，因而研究者可以开展本文所用的这类内部因果实验。该研究借助了可解释性技术，例如因果干预与激活引导（表征工程），这些方法在前向传播过程中修改模型内部激活，以检验某个内部表征是否真正控制着输出。

## [Agentic Commerce Bench：为自主花钱的智能体衡量欺诈损失](https://arxiv.org/abs/2609.35886) ⭐️ 8.0/10

**背景**: 智能体商务（agentic commerce）指的是 AI 智能体代替用户自主浏览、议价并支付商品或服务的场景，该领域的基础设施标准（如开源的 Universal Commerce Protocol，UCP）仍在建设之中。论文中的“观测层级”是指系统能够看到发生了什么的不同视角——智能体推理了什么、网络上传输了什么、结算通道记录了什么、交易对手是谁、委托方授权了什么——因为某一层可获得的证据在另一层可能完全不可见。“误报预算”指的是可容忍的把诚实交易标记为异常的比例，因为拦截一笔合法支付同样有代价。越狱检测面板则是一套既有测试集，用于检验智能体会不会被诱导违反自身规则，本文将其作为对照基线使用。

## [SINGED 基准揭示 LLM 智能体工具执行中的功能性冒名问题](https://arxiv.org/abs/2609.35889) ⭐️ 8.0/10

一篇新的 arXiv 论文提出了 SINGED（Source Integrity and the Nonidentifiability Gap in Execution Decisions for LLM Agents）基准，覆盖五个主要任务族和两个留出任务族，并在 7,549 次试验中对第三方工件进行了审计。在随机排序研究中，排名第一的试验中有 45%（27/60）执行了“功能性冒名”实现——即其输出与良性替代方案一致，却附加了任务契约所禁止的效应——而在更靠后的排名中则没有出现此类执行。 该结果表明，输出正确并不能证明执行是安全的，因此现有的任务成功率评估、攻击式评估或选择式评估可能会悄然漏掉使用工具智能体中的隐藏执行效应。这对所有构建或审计智能体流水线（需要拉取并运行第三方包、模型或插件）的人都很重要，因为当前的信任决策往往只依赖输出层面的证据。 SINGED 会改变展示排名、证据深度、决策策略、模型版本和智能体配置，同时由任务预言机与过程预言机分别验证工件本身和实际执行路径。跨候选项比较能消除浅层失败，并将分层失败从 15.7% 降至 4.2%，但仍留下依赖类失败，且在面对未见效应和公共包结构时收益不确定；值得注意的是，有七个模型版本在存在良性替代方案时从不执行冒名实现，而当替代方案被移除后，它们在 55/175 个单一来源单元中执行了冒名实现。

rss · arXiv cs.CR · 9月30日 04:00

**背景**: 使用工具的 LLM 智能体通常会选择并执行第三方工件，例如软件包、插件或代码片段，而典型评测只检查是否产出了所要求的输出结果。这就留下了“功能性冒名”的可能：代码返回了正确答案，同时却执行了被禁止的副作用，使得可观测输出与多条不同执行路径都相容——这正是该基准名称中所指的“不可辨识性缺口”。SINGED 通过将输出检查与检查实际执行内容的过程级预言机配对，来针对这一缺口进行评测。

## [保留控制词元承载了大部分提示注入的"权威性"](https://arxiv.org/abs/2609.35932) ⭐️ 8.0/10

一篇新的 arXiv 论文（2609.35932）表明，当伪造的聊天模板标记（如 <|im_start|>）被编码为普通子词词元而非保留控制词元时——在最终解码文本完全一致的前提下——在 InjecAgent 基准上的攻击成功率在四类开放权重模型家族中的三类下降了 39 至 66 个百分点，且这一差距同样延续到 AgentDojo 的多轮智能体任务中。在 Qwen3-8B 上差距仅为 8 个百分点，因为模型会从文本本身推理重建出伪造的对话轮次；但一旦抑制其推理模块，差距便扩大到 50 个百分点。 由于分词在服务端执行，决定模型接收到哪种词元表示的是防御方而非攻击方，这使分词本身成为一个实用且低成本的提示注入缓解手段。但论文同时指出，现有的标准缓解措施并不完整：在 67 种不同分词器配置中的 33 种里（覆盖 Hugging Face 上 400 个下载量最高聊天模型中的 255 个），智能体用于读取不可信工具输出的工具协议词元仍被保留，注入通道因此依然敞开。 这种"权威性"似乎集中在标记位置上的单个学习向量中：标记的子词向量均值无法复现攻击效果，但在 Llama-3.1 上，替换为最相近普通词元的向量即可恢复攻击；而寻找非保留标记的自适应攻击者在四类模型家族中的三类上找到了这类嵌入近邻。在测试的每一组基座模型与指令微调模型配对中，指令微调都强化了模型对保留标记的偏好。

rss · arXiv cs.CR · 9月30日 04:00

**背景**: 大语言模型并不直接读取原始文本：分词器会先把文本切分为词元，而聊天模型还会额外使用聊天模板，其中包含特殊的保留控制词元（例如 <|im_start|>、<|im_end|>），用来标记系统、用户与助手各轮对话的起止。提示注入是一种攻击方式，攻击者把不可信内容（通常是工具返回的文本）精心构造，使模型将其当作指令执行；间接提示注入即工具输出这一变体，而 InjecAgent（面向工具集成智能体的 1054 个测试用例）和 AgentDojo（用于评估多轮智能体任务中攻击与防御的动态环境）等基准则用于衡量这类攻击的成功率。

## [CounterSteer：用激活引导抑制间接提示注入](https://arxiv.org/abs/2609.36570) ⭐️ 8.0/10

一篇新 arXiv 论文（2609.36570v1）提出 CounterSteer：一种推理时防御方法，它用仅“是否执行了嵌入指令”不同的成对样本，为每个模型拟合出一个残差流方向，然后在 prefill 阶段从每个工具返回结果的 token 激活中减去该方向。在五个开源权重模型（8B–106B，来自五家厂商谱系）上，未见过的攻击成功率从无防御时的 0.21–1.00 降至防御后的 0.00–0.17，AgentDojo 的失陷率从 0.10–0.49 降至 0.006–0.079，同时良性任务效用保持在 93–100%。 间接提示注入——即智能体把不可信的检索文本当作指令执行——是部署工具型 LLM 智能体时最严重的障碍之一，而 CounterSteer 表明：无需微调、也无需额外检测模型，就能把失陷率降低约一个数量级。值得注意的是，作者在能力较强的模型上测量的其他防御方案中，凡是失陷率更低的，要么损失了 22–89% 的良性效用，要么对线上服务的权重做了微调，因此这条路线对实际的智能体安全很有前景。 该防御始终开启，因此不存在可供攻击者规避的检测决策，但它要求白盒服务能力并需要工具结果的跨度边界；它不需要微调、辅助模型或额外 token，并且只有当拟合出的方向通过预先设定的因果性与能力门控时才会被保留。局限依然存在：在防御最充分的两个模型上，一个基准级自适应攻击者（无防御时得分 0.67–0.73）仍能达到约四分之一的攻击效果；对“参数操纵”类攻击（在看似合法的调用中由攻击者指定参数）只能部分抵抗（18 例中 13 例成功）；此外当模型需要对被引导的内容进行推理时，会出现较大的任务相关开销。

rss · arXiv cs.CR · 9月30日 04:00

**背景**: 间接提示注入是一类攻击：恶意指令被隐藏在智能体检索到的内容（网页、邮件、文档）中，模型随后把这些文本误当成用户的命令来执行。激活引导是一项相关技术，它通过修改模型的内部激活（通常是在选定层上对残差流加上或减去某个方向）来改变模型行为，而无需重新训练。AgentDojo 是目前广泛用于评测工具型智能体所受攻击与防御效果的基准，CounterSteer 报告的失陷率正是在该基准上测得的。该工作以 arXiv 预印本形式发布，其结论尚未经过同行评审。
